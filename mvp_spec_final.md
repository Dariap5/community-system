# Финальный MVP — спецификация (версия 3, итоговая)

## Принципы

1. **Настройки — в `.env`**, не в админке. Токен, платёжка, контакты.
2. **Продукты — в коде** (`app/products.py`), словарь.
3. **Треки комьюнити — через воронку**, не отдельным разделом админки. Выбор трека = нажатие кнопки в шаге, после которого воронка ведёт на оплату именно этого трека.
4. **Типы контента в шаге:** только текст, фото, документ. Остальное — потом.
5. **Без preview, без тест-отправки.** Тестируем через Telegram напрямую.
6. **Админка без авторизации**, доступ по secret URL.

---

## Как реализуется выбор трека

В воронке "Комьюнити" после сообщения "Выберите трек" идут 3 кнопки — "Карьера", "Бизнес", "Саморазвитие". Каждая имеет действие `goto_step` на соответствующий шаг.

Каждый из трёх шагов (по одному на трек):
- Присваивает тег (`track_career` / `track_business` / `track_selfdev`)
- Отправляет текст с описанием трека
- Показывает кнопку "Оплатить" с `pay_product: community`

После успешной оплаты бот видит у пользователя тег трека и отправляет правильные ссылки:
- Ссылка на общий чат комьюнити (одна и та же для всех)
- Ссылка на чат конкретного трека (зависит от тега)

Ссылки хранятся в `.env`:
```
COMMUNITY_CHAT_URL=https://t.me/...
TRACK_CAREER_URL=https://t.me/...
TRACK_BUSINESS_URL=https://t.me/...
TRACK_SELFDEV_URL=https://t.me/...
```

Никаких таблиц `Track` в БД, никаких отдельных экранов — всё через воронку.

## Итоговый scope MVP

### Бот
- `/start` и `/start XXX` с deeplink
- Текстовые, фото- и документ-сообщения
- Задержки между сообщениями (в секундах) и между шагами
- Inline-кнопки с 4 типами действий: URL / goto_step / add_tag / pay_product
- Меню пользователя (Reply Keyboard, 4 кнопки): Продукты, Мои подписки, Поддержка, Оферта
- Оплата через ЮKassa/Robokassa + webhook
- Автопродолжение воронки после оплаты

### Админка
- **Воронки** — список, создать, дублировать, архивировать, вкл/выкл
- **Редактор воронки** — список шагов с drag&drop, deeplink, поведение при пересечении
- **Редактор шага** — название, задержка перед шагом, wait_for_payment, сообщения (текст/фото/документ) с задержками, блок кнопок (до 4 типов), теги после шага, следующий шаг
- **Пользователи** — просмотр таблицы, без действий
- **Аналитика** — общие цифры + процент прохождения шагов воронок

### БД
7 таблиц: users, user_tags, user_funnel_state, funnels, funnel_steps, purchases, scheduled_tasks

## План реализации — 5 промптов

1. **Промпт 1 — Фундамент:** проект, Docker, БД, модели, Pydantic-схема шага, seed
2. **Промпт 2 — Бот:** движок, обработчики, меню, выполнение шагов
3. **Промпт 3 — API + Webhook:** REST для админки, ЮKassa webhook
4. **Промпт 4 — Админка:** все экраны (воронки, редактор шага, пользователи, аналитика)
5. **Промпт 5 — Деплой:** на VPS, настройка ЮKassa, финальные тесты

Время: **3-4 дня** при плотной работе. Один промпт = один рабочий день или полдня.
